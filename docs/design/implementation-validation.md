# 持久会话实施验证

实施与最终复核完成。本文件记录实现边界、可重复的验证方法和实测结果。机器可读摘要见 [验证记录](implementation-evidence.json)，决策过程见 [实施记录](implementation-decisions.tsv)。

## 实施范围

领域层保留会话、工具执行与效果裁定。原生工具 ID 原样保存，完整调用地址携带会话、turn 和 step。没有仅为缩短文件而另拆一个领域会话模块。

应用层新增 `session_document.rs`，统一保存调用来源、请求准备、响应证据、冻结视图和故障确认。新增 `context_policy.rs`，负责整轮选择、必须保留的未知效果和完整请求预算。模型端口接收应用定义的审核对象，适配器负责将其编码为带来源的数据。JSONL 适配器拥有格式、文件锁和原子替换。

新增 [真实验证脚本](../../scripts/verify-live-sessions.py) 属于开发验证工具。它调用编译后的 COLA 可执行文件，认证信息仅留在转发进程内存。脚本没有另实现会话恢复、上下文选择或工具执行。

写入故障矩阵包含发布前失败和发布后返回持久性未知。它证明应用停止后续 I/O，并在下次取得锁后重新读盘恢复，不代表做过硬件断电试验。锁测试运行独立进程；验证环境为 macOS 本地文件系统。

## 真实 provider 验证

通过转发器调用真实 DeepSeek 与阿里云百炼的 Responses API。COLA 配置使用本地转发地址与占位凭证，上游请求和响应正文原样转发。每轮都启动新的 COLA 进程，持久会话始终相同。

| Turn | 入口 | 模型 | 行为 | HTTP 调用数 |
| --- | --- | --- | --- | --- |
| 1 | CLI `/new` | deepseek-flash | 读取当前文件 | 3 |
| 2 | 新 CLI `/use` | qwen3.8-max | 读取新值并回忆旧值 | 3 |
| 3 | 新 CLI `/use` | qwen3.8-flash | 读取新值并回忆旧值 | 3 |
| 4 | 新 CLI `/use` | deepseek-flash | 仅回忆历史 | 1 |
| 5 | 新 CLI `/use` | qwen3.8-max | 仅回忆历史 | 1 |
| 6 | 新 Web 进程 | deepseek-flash | 读取新值并回忆旧值 | 3 |
| 7 | 重启 Web 进程 | qwen3.8-max | 仅回忆历史 | 1 |

每个读取 turn 都只调用一次真实 `read_file`，并且经过真实 reviewer。单个文件在下一读取 turn 前被覆盖。最后四个不同随机值只能从先前的持久记录得到。只回忆的 turn 不调用工具。

脚本独立读取最终 JSONL，核对每次调用的实际请求字节哈希、响应正文、请求与返回模型、HTTP 状态、捕获完整性、接受的 step、原生调用 ID 与执行结果。新 turn 的第一条请求不包含旧 turn 的原生调用或 reasoning 项，历史模型审计字段也未进入语义历史。审核事实应位于数据消息中。

最终代码 `6d86241` 的完整真实运行通过。七个新进程、15 次 HTTP 200，生成状态全部为 completed；四次工具执行均保持原生 ID，四个随机值均按顺序回忆。审核事实在数据消息中，未进入 system。此前两轮完整运行也通过，最终结果以此轮为准。原始档案和请求响应保留在本地 `.audit/durable-real-providers-release/`，PR 仅发布不含凭证和原生思考正文的摘要。

复现命令如下，脚本会在终端分别读取两个 key。

```sh
cargo build --locked
python3 scripts/verify-live-sessions.py \
  --binary target/debug/cola \
  --evidence .audit/my-live-session-run
```

首次运行曾把百炼在有序列表前说明当前值的文本误判为乱序。脚本现在检查完整有序序列是否存在，并保留了失败现场。它也拒绝 `python -O`，并在超时或中断时终止、必要时杀死并回收 CLI/Web 子进程。

## 明确边界

- v1 JSONL 不做迁移。使用新目录或由操作者删除旧会话，库不会自动删数据。
- 默认最近八个可选 closed turn，加上未裁定效果所在 turn；完整请求默认 64 KiB。初始选择与原生链增长都检查此上限。工具自身允许的输出可能超过模型请求预算，届时明确失败，需要调整配置；不会截断工具结果。reviewer 准备失败继续阻断，必须明确确认。
- 字节预算可通过 CLI/Web 配置和 Rust 策略调整。没有自动获取模型窗口或精确 token 计数。它不构成任意模型容量的通用保证。实际目标模型的限制以其 [DeepSeek 官方说明](https://api-docs.deepseek.com/quick_start/pricing/) 与 [百炼官方说明](https://help.aliyun.com/zh/model-studio/qwen3-8-max) 为准。
- 原生载荷保留精确字节，当前存为 JSON 整数数组。完整请求、响应和冻结前缀会增加快照大小与重写量。此次没有性能目标或测量，不宣称存储效率改善。
- 新 turn 使用语义历史，不携带旧 turn 的原生思考。原始响应完整归档，但没有证明回答质量与保留旧原生思考时相同。
- Anthropic 协议由本地 HTTP 与 CLI/Web 夹具验证，尚未使用真实 Anthropic 服务验证。此次真实请求均为 Responses 协议。没有验证网络文件系统锁或 Windows 持久性。


## 审查取舍

已修复的 correctness 与边界问题均有回归或独立运行证据。完整正文的字节预算、准备失败时 reviewer 继续阻断、旧格式拒绝及整份快照的存储成本保留为本次明确策略，没有借助截断或自动放行消除错误。

审核者提出的载荷编码与前缀去重优化暂未采用，当前格式保留任意原始字节，包括非 UTF-8 的畸形或不完整响应。全量快照与整数数组的成本在上方明确记录，未以此宣称容量或速度目标。列表遇到损坏或旧格式会失败；此行为要求操作者清理不支持的旧档案，库不会静默跳过它们。它不是旧会话迁移方案。

审核者指出的错误文档已修正。进程可共享存储根目录，写入互斥粒度是会话；未知字段的拒绝范围也按实际 schema 说明。
